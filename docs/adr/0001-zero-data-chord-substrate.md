# 基座是零数据、零预设能力的 Chord 宿主

Moonan 的 `alpha5` 把「内核」定义得太宽：它持有 SQLite 数据库、模型网关、Agent 运行时、五条预设能力契约，以及面板清单。这带来两个后果：任何新功能都必须先改内核；而「内核」里的大部分代码只对一个用途（AI 角色扮演）成立。

我们决定把内核整个删掉，只留下基座：

- **零数据库**：基座不建表、不写配置文件、不保存任何业务状态。插件若需要持久化，自己用 `self.resource` 打开自己的 SQLite 文件。
- **零预设能力契约**：没有 `HostPaths`、`AgentAdmin`、`ModelAdmin`。插件需要什么，就用自己的契约向内核之外的世界要；基座不替它们转述。
- **零功能语义**：基座不认识对话、模型、转录、面板。它只做四件事：建 Chord 宿主、监听端口、按 URL 装载插件模块、把 HTTP 交给 `Routes` 注册表。
- **唯一的基座契约是 `Manifest`**：一个只读远程对象，公布已加载插件的浏览器切面 URL。浏览器要靠它才知道该 `host.load` 哪些模块，而这份信息只可能由装载者知道。

**Considered Options**

1. 保留一个极简 `platform.db` 存语言与偏好。被否掉：一旦基座有了第一张表，第二个功能就会往里加表，删掉内核的努力会退回去。语言这类偏好属于浏览器，`localStorage` 足够。
2. 保留 `HostPaths` 让插件知道数据目录。被否掉：这等于承认「插件都需要文件系统」。不需要持久化的插件不该被迫接受一个路径契约；需要的插件完全可以自己从环境或参数取。

**Consequences**

- 基座不再能给插件「提供能力」，只能给插件「提供环境」。插件之间的横向依赖改由跨插件契约承担。
- 卸载一个插件等于删掉它的包与它的数据文件，基座侧没有任何残留需要清理。
- 升级基座与升级插件彻底解耦：基座不认识任何插件，也就不会因为插件改动而需要发版。
