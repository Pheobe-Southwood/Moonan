# 0004：ActBlock——单副本、不落库、每次请求先摘后挂

- 状态：接受
- 日期：rc1

## 背景

需求原文要求三件事：

1. 无论何时主 Agent 调用任何 tool、收到任何 user 消息，都要在"tool 结果末尾 / user 消息末尾"追加
   下一步可用的 actions，以及每个 action 的参数，并追加一句「act以外的工具不受限制，均可调用」；
2. 为了避免下一步可用工具占用过多上下文，每当主 Agent 输出内容时就删去上次那一段，接受略微的缓存失效；
3. 对话窗左侧的角色消息只是"一次 tool 调用的产物"，不该额外触发下一轮。

## 决定

- **形态**：一段以 `<!--moonan:act-block-->` 开头的文本块，内容由当前**可用** action（前置条件已求值）渲染，
  末行固定是「act以外的工具不受限制，均可调用」。
- **位置**：挂在「本轮最后一条 tool result」，没有 tool result 时挂「最后一条 user 消息」，
  两者都没有时挂最后一条能承载文本的消息。**一轮内只挂一处**。
- **单副本**：在每次请求前（`transformContext`）先对**模型视图的副本**摘掉所有旧块，再挂新块。
  因此任意时刻模型看到的最多一份，且块的位置总在"最后一条消息末尾"。
- **不落库**：`transcript` 表里存的永远是原文；ActBlock 只存在于模型视图。日志窗默认显示原文，
  可切换到「模型视图」看含块的渲染结果。
- **角色消息**：`conversation.send_message` 这个 action 通过 `writeSidebar` 写一条 `write` 消息——
  进历史、进 UI，**不触发生成**。

## 理由

- 摘挂作用在副本上，历史不受污染：这直接消灭了"历史里出现多份 actions 列表"的可能。
- 前置条件（`available()`）在每次渲染时重新求值，因此"发消息前必须先打开某个界面"这类规则
  不需要额外机制——它只是让某些 action 不出现在块里。

## 后果

- 好：模型看到的块永远是最新的；上下文增长与 actions 数量无关，只与"一份块"有关。
- 差：每次请求的前缀缓存都会在块的位置失效。这是需求明确接受的代价。
- 差：块的渲染依赖"最后一条 tool result"这个位置概念，因此 `act` 工具的 tool result 必须能被识别为
  "本轮的 tool result"——通过 `details.agentId` 标记实现。
