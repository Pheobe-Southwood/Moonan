# 回合跑在 root 里，task 只做可重启的后台活

alpha3 的 `AgentContract.send` 直接 `await agent.prompt(...)`。方法调用会一直挂到回合结束，浏览器一刷新，引用释放，回合跟着断；内核只好在启动时把每个 Agent 对象「钉住」来绕开这个问题。

alpha4 按 chord 的代码持有语义拆开：

- `send` 只把消息放进 Agent 对象的 `inbox` 状态单元，**立即返回**（ACK）。
- `inbox` 的监听器在 commit 阶段启动，看到队列非空就 `api.root(...)` 起一个 **root** 跑回合。root 会被「祖父化」：重载时它继续在旧代码上跑完，写的是共享的单元格。
- `self.task` 只放**可重启**的后台活：chat 的 2 秒合批循环。task 在每次重载时被停掉并用新代码重启；未发的批次留在 `pending` 单元格里，新代码接着发。

持久化用**水位**而不是「内存里第几条」：回合开始前按 `lastSeq` 从库里补齐别人追加的行，回合中只追加水位之后的消息。这样旧代码的回合和新代码的回合可以共存，不会写出重复行。

**Considered Options**: 把回合也放进 `self.task`。被否掉的原因是 task 在重载时会被中止并重启，一个跑了一半的回合会被腰斩；root 的语义正好相反。另一个选项是引入一个外部队列，代价是又一个需要持久化和重试的组件。

**Consequences**: 连续两次重载时，第一次遗留的 root 会在 `taskStopDeadline`（默认 5 秒）后被中止。`send` 不再返回回合结果，想知道「说完没有」要订阅 `phase`。
