# 只有 send_message 的输出进入对话窗

模型输出的普通文本一律视为内心独白，只进日志；用户能看到的一切都必须由 `send_message` 工具产出。这样「角色说了什么」和「模型想了什么」不会混在一起——角色扮演里，模型的推理往往会剧透人设，直接显示会毁掉沉浸感。

副作用是模型必须主动调用工具才会说话。系统提示词里写明了这一点，聊天插件也把 `send_message` 的标签设成「向对话窗口发送消息」，让模型在工具列表里更容易选它。

打开或切回对话窗只读取已有气泡，不向 Agent 发送提示词，也不创建回合；只有用户输入才会触发模型。

**Considered Options**: 直接把助手文本当回复，`send_message` 只作为附加。被否掉，因为那样每一句台词都会被模型的分析性文字污染；反向的「过滤掉文本只留工具」又做不干净。
